# 实质分析验收（2.0）

使用[研究主流程](research-engine.md)。这是报告放行门，不能用字段齐全或搜集数量代替。

| 检查 | 合格证据 | 不合格表现 / 返回位置 |
| --- | --- | --- |
| 领域理解 | 解释历史问题、强先行、瓶颈原因、输入增量和当前路线转折 | 通用背景/文献罗列；返回A |
| 机制解释 | 从部件/步骤分工，经有原件支撑的机制、测量对象和工程失效，推到任务输出；解释同任务替代并指出可检验预测 | 只有术语、数字表、笼统“系统表现不同”；互连测试和整机测试混用；返回[领域解释](field-understanding-and-causal-explanation.md)继续读原件 |
| 任务与需求 | 用户、合格输出、真实残余需求及来源 | 行业大所以价值大；返回A/D |
| 应用端基线 | 有应用主张时，在评价论文应用推理前先由需求方/运营方/工业资料说明真实任务、当前方案、主导瓶颈、替代及未来采用门槛；说明工业来源的角色、利益关系、交易成熟度和数据血缘 | 先引用论文引言/小同行共识来证明需求，或把厂商公告、融资、意向书、行业TAM当订单；返回[应用端先行](application-side-first.md) |
| 模型 | 关键变量到系统输出的关系、尺度及假设 | 只有模块名或“存在挑战”；返回C |
| 强比较 | 同任务同质量的实际替代，区别实验与产品基线 | 只沿用作者弱基线；返回C/D |
| 决定性推导 | 删除/替换/补齐或适用的界限、规模、阈值分析 | 只说没有证据/无法判断；返回E |
| 科学价值 | 具体知识增量、意义与相近获取路径比较 | 因无应用清零或基础研究自动免责；返回E |
| 反方检验 | 最强正/反材料及其为何改变或未改变判断 | 只收集与用户预期同向资料；返回B/D |
| 社区与从业者洞见 | 实查入口、关键原讨论/回应、争点核查和处置，或有依据的受限/不适用说明 | 只找负面论文、列论坛名而没读、转引专家判断；返回B/D及社区调查 |
| 经济意义 | 参数、数量/工时、边界、敏感性与对应决策 | 任意数相乘、相邻价格填空；返回E |
| 未知处置 | 是否会改变行动、已做的重建、翻转条件 | 精确总账未知吞掉全部判断；返回F |
| 决策力量 | 明确支持/不支持哪类经费、原因与可验收下一步 | “建议关注/进一步研究”；返回F |
| 投入取舍 | 目标、主导约束、输入边际作用、可行替代与当前行动相连；有真正改判条件 | 只给申请方补证清单、用“我认为”包装无依据断言；返回F |

不适用项给出技术理由。纯科学主张不必通过产品需求/经济模型，但知识增量、反方和科学资源比较仍需完成。

## 结论强度

- 原始观察支持所测条件下结果。
- 有效逻辑/物理界限支持限定设计域内不可能或不适配。
- 完成同任务的替代反例可否定普遍必要性；判断无优势还需比较重要指标。
- 匹配支配/稳健阈值支持限定场景的低价值或不值得推广。
- 完成检索后的无结果支持明确的“未找到有效证据”和相应举证/资金决定；本身不证明全球绝无价值。缺席、反证与建议分开，详见[来源协议](research-saturation-and-zero-rule.md)。

正文先给实质判断，再给有效范围与改变它的证据。不用抽象未来可能性撤销已成立的负面判断；不为强硬语气扩大证明范围。

## 三个读者检查

1. 读者能否用自己的话解释最重要障碍为何出现？
2. 读者能否知道论文实际推进了哪一步，以及多大程度改变瓶颈？
3. 读者能否据此区分科学探索、工程验证与规模推广的不同资金决定？

抽取一个关键指标和一个强替代，读者还能否说出“谁测的哪个部件，在什么工况下得到什么读数，该读数怎样改变最终任务表现，另一方案把限制放在哪里”？若正文只给结论或数字，机制解释不合格。

有一项不能，报告返回研究，不以多写免责声明或再列数据库修补。

### 决策表达核对（2.1.1）

读完决策段，应能回答：现在支持/不支持什么？为什么是这个约束决定取舍？本工作改变了多少？同样资源还有什么可行去向？什么事实会改变行动？关键答案缺失则返回研究，不能靠换形容词通过。强结论与用户预期一致不算正确性证据；**只能在证据充分时明确写“值得优先支持”**，须逐项核对该阶段的目标贡献、可行替代和资源取舍依据。不以正负平衡、未来可能性或没有反证作为放行理由。

## 防止自评虚假通过（2.1）

**两版解释深度也须放行。** 按[读者解释检查](explanatory-depth-and-public-writing.md)逐项定位正文：领域来由、成果本体/运作、具体创新、替代运作、瓶颈来源、任务收益和资金因果链。专业版只有技术名词/摘要或大众版只有短结论时，标部分完成并补写；知识本身未清楚则返回研究。不能拿篇幅变长或标题齐全声称通过。

大众正文若主要是“需要比较/不能证明/不排除”“本稿继承/范围限制”或可套任何领域的评价原则，解释性验收不通过。定位已经给出的具体答案；缺答案则补研究，答案有了而表达抽象则重写。保留会改变当前判断的必要条件，其余内部记录移至文末/附录。

**篇幅硬门：** 按[5.1节计数口径](explanatory-depth-and-public-writing.md)检查专业/大众各自的A与M，100×M≤A才满足比例要求；缺逐句分类记录、将套话改名为分析、靠冗余填字或删除决定性限制，均不通过。比例通过不替代机制与比较的实质验收。

- 每项引用正文的具体推导和证据位置，标完成/部分/失败/不适用；没有做的比较不能由参数列表或他人的结论替代。
- “非通用”不自动证明专用用途低价值；非通用加速器同样可能有用，仍须比较其特定任务。
- “科学贡献高”也要举证。没有最近强先行、同知识目标替代和意义分析时，只能确认已核的贡献单元。
- 无对象任务映射/实测参数的假设算例不算对象定量验证；已有公式也不能跳过其适用条件。
- 文件存在、关键词、来源数量、脚本退出码只检查产物，不能让实质条目PASS。结构化报告/契约或关键调查未完成时，交付状态标明部分完成，不自称完整审计。
- 结论所依赖的决定性未读全文、争论回应、具体可访问成本/任务线索必须处理，或明确受限如何影响该项放行。旧报告的“通过”可在复核记录中撤回，不能让历史自评锁住当前结论。
