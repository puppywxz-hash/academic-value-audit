# 从实际任务反推需求、市场与社会价值

实际执行必须同时落实 [功能必要性与能力迁移](functional-necessity-and-transfer.md)：任务是否需要新增功能、强整机替代是否已解决、专用实验到所述用途缺哪些能力；仅检索销售/投资不能完成应用潜力判断。

对产业或社会价值的关键主张必读，包括尚未商业化的潜力主张。执行本文件并使用 [需求分析记录](../assets/demand-analysis-template.md)，接回既有证据、要求、比较、模型及 M1/M8 记录。纯知识贡献无应用主张时说明不适用；研究对象有应用宣传时仍审该宣传，不强迫全部基础研究有客户。

具体资料搜集按 [非学术搜索协议](nonacademic-search.md)建立矩阵和机构/记录清单；结论按 [两层评价](two-level-assessment.md)归第二层，已核需求可用于第一层应用导向意义的判断。不要把取得原件、应用价值成立及学术增量合为一个状态。

在实际评判目标论文、专利或项目的应用主张前，必读并执行[应用端先行](application-side-first.md)：先定位买方/运营任务、现用方案及产业瓶颈，再判断输入能否改变瓶颈。按其来源能力区分实际运行/交易记录、采购需求、制造/资格材料、行业分析和供应方宣传；学术资料负责技术机理时不被排除，但不能单独建立客户需求。

涉及技术标准/测试/认证，必读 [标准检索](standard-retrieval.md)，将官方目录定位、原条款读取、采用约束、场景/方法可比性和必要门槛资格分开；标准的存在不自动证明残余需求或实际净收益。若评价奖励对应用的要求，另按 [奖项规则](award-assessment.md)，不要把奖励资格混成工程使用要求。

## 1. 建立两条取证分支

- 成果端：忠实拆出作者/第三方的应用、受益者、优势、规模、期限及因果承诺，作为待核命题。
- 需求端：从终端任务、使用方和现有解决方式检索。初始查询尽量不用材料名、论文作者、实验指标和小同行品牌；按产品、流程、工况及采购主体寻找实际记录，再与成果连接。后续可用技术名查采用与机制。记录实际查询；这不是声称实施了盲法。

任务基线不得延后到应用结论之后。先将论文用途原话变成待核命题，随后从独立的买方、使用方、运营、生产或采购路线查当前基线及瓶颈；来源关系按[应用端先行第3–4节](application-side-first.md)判定。只有工业侧现实模型建立后，才用全文、专利和技术资料验证成果接上了哪一段。

每个场景固定时期、地区、产品/服务、使用环境和受益单位。区分使用者、购买者、付款者、决策者、受益者及承担风险者，可由同一主体兼任，但不能默认相同。产业客户、终端消费者、政府采购、关联方、补贴试点分别建情境。

逐环核查：实际问题 → 现有方案下的残余损失/约束 → 值得解决的需求 → 本成果的系统增量 → 可交付及可采用 → 增量净收益 → 可归于该研究的贡献。任何一环成立都不替后续举证。未来潜力不要求已经销售，但须说明哪些环节只是条件、预测或未知。

## 2. 记录与命题匹配

| 要回答的问题 | 应找的记录及获取方向 | 能证明的范围和关键限制 |
| --- | --- | --- |
| 谁在什么情况下遇到问题，发生多频繁、多严重？ | 使用方工作流程、设备/服务运行、停机/维修/报废、质量与损失台账；目标人群调查和行政统计 | 核对产品/版本、时段、暴露分母、选择和漏报。案例/投诉能提示问题，不能自动给总体发生率 |
| 当前怎样解决，还有什么没解决？ | 在用方案、操作/维保手册、产品技术文件、验收和实际性能；使用方成本、等待/失效记录 | 锁定功能与实际服务质量；成熟方案参数不等于全部现场效果。查组织/流程改进与不改变方案 |
| 改善什么才值得，最低需要多少？ | 原始需求调查、功能规格、采购技术/商务附件、服务目标；有来源的使用频率、寿命与容许失效 | 条款、理由和适用性分别核查；品牌定向、过度要求、研发目标和偏好不当全行业必要门槛 |
| 谁愿意且有能力支付，什么条件下选择？ | 预算、成交合同、付款、续约/复购、退货/停用；未采用者、取消/变更/流标记录 | 招标≠成交，成交≠运行或净收益；意向≠支付。核对补贴、关联交易、采购任务与自主竞争，不预设公共采购无价值 |
| 为什么实际会换，怎样投入使用？ | 兼容/认证/验证条件、实施合同、人员培训、停机切换、供应与维修保障、实际采用/流失原因 | 收益人和付费人不一致、风险、锁定和制度约束可阻碍采用；未采用不能单独归因性能差或无需求 |
| 新方案比可行替代增加了多少净收益？ | 相同任务的交付质量、运行投入、全生命周期成本及对照；客户/运营方具体收益而非供应商口号 | 计入购买、封装/集成、质量、维护、更换、风险及切换；总变化不自动由技术造成，整产品收益不全归材料/论文 |
| 有多少任务真正适合，可重复多久？ | 已核实的设备/客户/服务人口分母、更新周期、适用约束、在用/复购队列 | 行业产值、融资与供给产能不等于可争取需求。可服务、会选择、可交付数量分开；缺采用参数不造渗透率 |
| 社会受益、损害及分配是什么？ | 疾病/安全/污染/资源/公共服务结果统计，实施与受益覆盖，可信对照、暴露及全链后果 | 真实需求、可产生效果、额外社会效果分别判断；产业利润/销售额不能替代社会净收益 |

这些是取证目标而非强制要求每次取得每种文件。按命题寻找最直接且适用的记录，并解释覆盖。公开原件、用户提供且有权使用的记录均可；商业保密部分不能保证取得。新闻、行业报告、访谈摘要只按实际提供的记录使用，转述回到原件。

## 3. 按步骤执行

1. **拆场景和角色。** 不把“光伏”“LED”“柔性电子”当单一需求。按相同任务、质量、购买机制和工况分段；已有主张先覆盖，另发现应用以审计者候选标识，不改写作者承诺。
2. **独立建立需求基线。** 先找现有服务及残余问题，量化频率、严重度、影响对象、现有成本/损失；没有观察数据可给明确假设，不能称已证需求。客户愿望需说明访谈对象、题目、选择及关系，保留负面/未采用者。评价授权不自动允许外联。
3. **挑战需求及指标。** 问“无需这种材料能否解决”“性能提高会改变哪个动作/结果”“当前水平是否已经足够”。由原始要求或有来源的使用推导定义最低条件；偏好与可支付溢价分开。要求记录按既有 basis_kind、validation_status 和 gate_eligible 填写。
4. **建立强可行替代。** 比较同任务的在用方案、成熟替代、系统/流程重设计及不行动；合理纳入当时可获得而未采用的方案，说明采用障碍。不可行的理想技术不能作现实基线，淘汰旧原型不能代表当前竞争水平。
5. **把论文接到任务。** 逐步检查部件性能 → 系统功能 → 使用行为/过程 → 最终结果，核查尺度、封装、寿命、环境、制造及附加负担。材料更柔软、效率更高或算法更快本身不能证明残余需求得到改善。
6. **分析采用和私人成本收益。** 按付款者/使用者分别算可追溯增量与全成本，使用 [计算方法](computation-methods.md)。收益差异、切换成本、风险和时间足以改变选择时写清。可算最高可承受成本/所需可靠性等阈值；关键实际值未知时仅给条件，不能宣称超过或低于阈值。
7. **分析社会结果与归因。** 使用下节；资源配置另审 M3/M5/M6/M7，不由大市场或社会问题严重直接推出大额投入合理。
8. **逐环裁定并回接。** 每环写支持、反对、最强竞争解释、状态、允许措辞和翻转证据。不把多环的“可能”串成已实现价值；尚缺关键公开资料时限制相应结论，也保留已经可靠成立的环节。

## 4. 社会价值的独立分析

- 明确公共结果、影响人群、地区/时间及评价目标的依据。购买力低、受益分散、公共品或外部影响可能导致真实需求缺少商业支付；商业需求和社会重要性不能相互替代。价值取向及群体权衡透明记录，不将其当自然事实。
- 写出研究 → 可用方案 → 实施/覆盖 → 行为或服务变化 → 结果的影响链；逐步核对依据。技术改善不能自动归因死亡下降、污染减少或公平改善。用可信实验/准实验、适当对照或贡献分析区分其它技术、管理、政策和环境作用；贡献分析不能凭空给精确归因比例。
- 先报告有单位的变化和全成本，如合格服务量、等待时间、能耗、暴露及健康结果；再按问题选择成本效果或成本收益分析。同服务比较成本须证明服务与损害可比；不同结果不能无权重随意相加。
- 非市场结果仅在估值方法、对象与适用性成立时货币化。实际行为推断偏好需处理收入、价格、选择限制和混杂；问卷意向保留偏差。异国单价、单次专家报价及政策权重不当普适事实。已有可归因结果但不能合理估价时，保留实物结果、分配和阈值。市场/社会结果必须按成果标识、实际任务、产品类别和通常结果记录开展跨地区多路径发现，查询适用索引/登记/当地来源，追完所有可访问线索并反向查漏；完整世界名册不是停止标准，也不能用来豁免任一可行路线。完成适用调查仍无有效结果证据时，明确列出所查行业/任务并说明该主张不能支持本轮扩大投入；机制反证与计量零值另按来源判断协议论证。仍有具体可访问且可能改变事件有无/归因的来源未查时不得结案。具体金额、长期社会因果或净收益可单独未识别，但不得以其未知把已闭环层级写成“无法判断”，也不能编造总社会净收益。
- 分列付款者、受益者及承担健康/环境/劳动/隐私等负担者；纳入实现、上游、使用、维护与处置。收入、工资、税收、补贴和融资不直接累加成社会收益；按评价边界区分转移与真实资源/机会成本，避免重复计算。就业等效果需有额外作用依据。
- 项目效果、技术贡献、该论文/研究组的贡献和公共资助的额外作用是不同层级；分别取证。不对无法归因的整条产业/社会效果指定比例。

## 5. 质量和完成要求

量化需求/市场/资金价值时接 [成本与需求重建](cost-demand-reconstruction.md)：实际任务分母、单位增量、采用与交付容量、替代支出、社会结果分别取得，用盈亏平衡/翻转值反查是否足够。无总账或不能货币化不直接结束；可行且决定性的重建未执行则分支未完成，不能只称来源受限。

必须展示需求端实际检索/原件/取得范围、角色、现有方案及残余问题、指标理由、强替代、采用条件、净效果和归因状态。只有供应方或同一小同行的用途论证时，明确需求分支没有独立验证；“工业界人士说”也需检查具体记录和共享前提。独立验证指不循环依赖被核前提，不要求所有记录都由圈外发表。

资料按证据—命题评价方法、口径、可迁移性及选择/披露；没有固定来源数量或圈外比例。损失、召回、投诉记录也须核对分母、漏报和因果；不能仅靠负面案例推整个行业无价值。采购可能存在定向要求，上市披露可能不披露客户，问卷可能过度承诺；权威载体不消除这些限制。

接回 S/E/C、requirements、comparisons、P/M、J、quality_audit 及 method_audit。目标与角色进入 decision_contexts（M1），功能单位/采用/分配/全链后果进入 impact_reviews（M8）；适用的商业兑现、公共投入、信息价值及组合沿用原记录。需求表是上述记录的可读索引，不新增未定义 JSON 字段。G4/G5/G6/G7/G10/G12 按原语义放行；填满表格或做完查询不等于需求成立。

完成标准是范围内决定性环节已有适用记录或明确缺失影响，支持与相反解释按同一规则处理。缺证可裁定“该应用收益未证明”；有匹配证据可明确“该场景增量小/成本不合算/主张被反证”。这些不自动外推其它场景、基础贡献或整个领域。

## 6. 方法来源及适配

- [NSF I-Corps 客户发现](https://www.nsf.gov/funding/initiatives/i-corps/about-teams)：从潜在客户、合作伙伴和产业主体检验商业机会；访谈帮助发现，不证明总体需求。本技能不照搬项目人数/次数，也不自动联系。
- [OECD Oslo Manual 第 7 章](https://www.oecd.org/en/publications/oslo-manual-2018_9789264304604-en/full-report/component-13.html)：区分客户/市场、需求、竞争与采购环境；本技能将其转成逐任务取证，而非创新调查评分。
- [FAR 48.101](https://www.acquisition.gov/far/48.101)：保持所需功能、分析采购/运行/支持成本的价值工程思路；不把美国采购规则当所有地区法规或真实效果证明。
- [财政部 2021《政府采购需求管理办法》](https://www.mof.gov.cn/gkml/caizhengwengao/wg2021/wg202005/202109/P020210917565943122846.pdf)，第 6–10 条：任务的技术/商务要求、实际需要及历史交易/后续运行调查线索；引用该版方法，不宣称完成当前法律适用核查。
- [Green Book 2026](https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government/the-green-book-2026) 与 [Magenta Book 2026](https://www.gov.uk/government/publications/the-magenta-book/magenta-book-central-government-guidance-on-evaluation-html)：公共后果、估值/分配、实施和反事实/贡献评价；方法移植要适配地区与对象，不默认套用英国估值参数。

上面的两分支、逐环记录和接回规则是本技能的综合设计，不冒称某指南原文规定了全部流程。实际数据源按对象定位，详见 [获取方法](acquisition-methods.md)。
