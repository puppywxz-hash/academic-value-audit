# 领域模块体系与专家贡献规则

本文规定如何把专业领域知识接入跨领域的 academic-value-audit。领域专家可以补充本学科的决定性约束、测量口径、技术路径和来源；核心技能仍统一负责证据质量、学术增量、真实需求、归因、价值分层、报告及最终裁定。

## 1. 推荐分层

```text
学术真实价值审计（跨领域核心）
  ├─ 不随学科改变的证据、归因、需求、价值、公共投入和报告规则
  ├─ 按需领域模块（半导体、能源材料、医疗器械、AI 等）
  │    ├─ 本学科主张分类和系统边界
  │    ├─ 第一性原理/技术模型及有效域
  │    ├─ 测量、制造、标准、强替代及专门来源
  │    └─ 常见跨尺度误推、分歧与场景案例
  └─ 对象审计产物（主张、来源、参数、计算、裁定和范围）
```

第一阶段以核心技能包中的可选 `references/domains/*.md` 协议为规范来源：由核心入口按任务触发，避免缺依赖时模型只看见领域技能、漏掉统一证据规则。半导体/CNT 模块是首个实例。领域模块不复制核心原则、JSON schema、证据枚举或总报告模板，也不定义独立价值分数。

当前已纳入的领域模块：

| 模块 | 触发条件 | 当前覆盖边界 |
| --- | --- | --- |
| [半导体器件制造成熟度与跨尺度迁移](domains/semiconductor-device-integration.md) | 材料/器件主张向阵列、CMOS/芯片、规模制造或产业应用外推 | 重点含 CNT 器件；其他半导体路线只可复用问题框架，技术门槛仍须逐路线取证 |
| [计算能力与任务优势](domains/computing-advantage.md) | 量子/光学/专用计算优势、通用能力与生产力主张 | 含GBS映射、强经典基线、端到端模型；初版定向试用 |
| [可形变电子](domains/deformable-electronics.md) | 柔性/拉伸向穿戴、贴肤和成像外推 | 形变分层、波纹/岛桥与任务；初版定向试用 |

未列出的领域不代表没有风险或不需要专门方法。若尚无经审核的领域模块，继续按核心协议审计并说明专门覆盖有限；不得自动把外部未审阅模块或用户倾向写成已批准规则。

Agent Skills 常见结构支持一个 `SKILL.md` 配按需 `references/`、`scripts/` 与 `assets/`；官方文档倡导把共享主线留在入口，将条件性材料按需披露。[OpenAI Skills 指南](https://developers.openai.com/api/docs/guides/tools-skills) 因不同运行平台的技能依赖/调用机制不完全相同，第一阶段不假定“安装一个领域技能就会自动继承核心技能”。如果未来单独发布领域入口，应是指向核心与领域协议的薄包装，并在发布包内明确捆绑/版本兼容，不能复制后各自漂移。

建议的仓库结构：

```text
skills/academic-value-audit/
  SKILL.md                         # 核心入口与分流
  references/domain-module-system.md
  references/domains/<domain>.md   # 经审核的领域方法模块
  assets/domain-module-template.md
```

这让读者/贡献者可按学科浏览，同时保持每个运行环境都能从核心技能找到其专用方法。若未来需独立安装或自动发现子技能，再另建薄入口和聚合清单；先验证实际复用需求，不提前制造多个相互依赖的技能。

## 2. 核心契约：领域模块能补什么、不能改什么

模块应能回答“该领域怎样把一个核心价值主张拆到可检验事实，以及何种证据足以跨到下一层”，而非为某领域写预设褒贬。

模块可以定义：

- 领域内常见成果/主张类型、系统层次、使用任务与关键术语的歧义；
- 适合该学科认识论的分析方式：机制/因果模型、解释框架、档案证据、定性比较等；不把物理因果模型强加给人文、历史或解释研究；
- 基本约束、专属计量单位、关键测试和失效模式；
- 何种现实要求可能成为必要门槛，门槛应从哪类标准、用户、产线或物理条件取得，以及何时只能记为路线图/情景；
- 发表时/当前强基线、同目标替代及跨尺度迁移所需证据；
- 适用的计算、工程、统计或因果模型，所需数据、假设、敏感性和不可用情形；
- 本领域重要的原始数据库、监管者、标准组织、制造者/使用者记录和专业档案入口，以及这些来源的局限；
- 学界内争议、不同研究路线和共同前提，及能使判断改变的反例/后续数据。

模块不得：

- 因领域热门、被奖/资助、引用高、同行一致或团队身份直接定高低；
- 把专家声望、该领域常用代理指标、路线图目标或宣传词改成无需核验的现实门槛；
- 按论文数量、作者/机构内外、媒体报道多少来投票或推断事实真假；
- 把局部科学贡献抹掉，或用整个领域未来潜力给本成果背书；
- 单方面改变核心 E/C/J/P/M/CTX 台账、G1–G12、M1–M9、既有枚举、专业/大众双版同源规则；确需改契约时走核心版本升级和迁移记录。

## 3. 专家贡献内容的最低结构

贡献者从 [模板](../assets/domain-module-template.md)开始，至少提供：

1. **边界和入口**：涉及哪些学科/技术/终点；哪些相邻主题不在范围；何时应加载、何时不能套用。
2. **主张地图**：从基础原理/材料到系统、产品/社会结果的层级；每一层对应可观察量和常见概念偷换。
3. **决定性方法**：模型/公式/检验步骤、定义和单位、适用假设、所需输入、错误来源、替代解释与停止条件。提供够用的操作说明，不只列名词/方法名。
4. **门槛与来源资格**：给来源类型/具体可检索机构或文件类别、时间版本、适用规则；区分法定/标准/客户/技术路线图/作者目标/情景阈值，严禁无出处的通用门槛。
5. **比较与反例**：强替代/先行技术、至少一个支持实例、一个不支持/限制实例、一个边界或争议实例。例子提供来源与范围，不把单例写成普遍规律。
6. **来源依赖与披露**：原始资料入口、二手材料的用途、共同数据/资助/人员/平台/引用网络和利益关联；说明哪类“独立来源”仍共享前提。
7. **核心技能映射**：领域证据如何进入原有主张、证据、比较、参数/模型和报告结构；哪些字段原样使用，任何新字段/枚举均须提核心维护者审核。
8. **维护元数据**：模块 ID、版本、兼容的核心接口、作者/贡献者、专业角色、利益/经费披露、来源最后核查日、变更摘要、待议分歧。

仅有“建议读哪些论文”、背景综述或口号阈值不够构成可执行模块。涉及高风险方法或定量模型时，应标出专家应有的资格与复核对象；模型不会因引用了模块便自动掌握未提供的专门技术。

## 4. 反小圈子与证据质量治理

开放贡献本身会引入新的偏差，因此应可追溯地审稿：

- 记录作者/评审者的机构、领域角色、资助/专利/商业或学术竞争利益；关系用于解释证据来源与范围，不作为事实真假的替代。
- 关键要求和应用效果优先回到原始标准、原始数据/测试、使用方/制造方记录或独立复现。领域专家综述能帮助定位争议，但不能替代被审工作之外的核验。
- 建立来源关系图/共同前提表；将同一个试验、联盟、数据库、产品网络的重复转述合并，防止“很多资料都说”伪装独立确认。
- 推荐每个领域模块由不同角色复核：至少一位熟悉核心科学/技术方法者，以及一位能检查真实使用、制造、临床/监管/经济或其它实际终点者；重要模块尽可能纳入未在贡献团队/共同资助链中的评审者。若做不到，披露限制，不谎称已独立审查。
- 对实质分歧保留不同证据及假设，指出什么观测可区分；编辑不能只因某结论不受主流欢迎或更受欢迎就删除。
- 修改门槛、比较基线或结论方法时写变更原因和影响的旧案例；不得静默追溯改规则以适配一个输入的预期答案。

领域模块评审者可以核“技术事实与专用方法”，但研究价值和公共资源建议仍要遵循核心两层评价与目标/机会成本；需在报告里保留模块的来源覆盖和专家未读/未复核边界。

## 5. 版本、审核与发布闸门

- 核心方法接口与领域内容分别版本化。领域协议兼容现行 schema 时标明，例如 `core_contract: 1.4`；不兼容/要增加必填字段则提出升级，不自行改现行对象。
- 每个模块的来源引用应可定位到文档/版本/章节/条款或数据集、访问链接、最后核查时间。易变标准、路线图、价格和规则须在实际审计日重新核验。
- 维护者检查范围清晰、模型可操作、适用域/负例齐全、门槛出处合格、利益披露、链接可用、核心接口映射及编码/文件名。
- 合并前做桌面方法审查；若宣称“行为已验证”，还需使用模块未提供预期结论的独立输入，检查漏项、错误外推、支持/反证对称和报告一致。案例测试检验证据链和边界，不检验模型是否同意维护者的政治/学术评价。
- 公布通过状态的准确含义：结构/格式检查、来源引用检查、专家方法复核、行为试用分别报告；不能把任一项写成完整审计可靠性证明。

初期采用轻量审核：核心维护者保留接口与跨领域原则的责任；领域模块维护者负责专业细节/更新；外部审稿意见和争议并列记录。规模扩大后再建立公开提案、版本发布与撤回机制，不预先设置无法维持的委员会形式。

公开接收外部贡献前，仓库维护者还需明确选择适用于代码/说明文本/数据资产的许可证和贡献条款，并区分“允许引用/链接”与“可以复制原文或数据”。不能把论文、标准、路线图、专有数据库的全文/图表直接打包进模块；优先记录可定位的书目信息、官方链接、短必要摘录和审计者自写方法摘要。当前项目内已先加许可状态检查项，尚未选择或发布任何开源许可证。

## 6. 对 CNT 模块的实际路由示例

输入“碳纳米管晶体管”时，核心技能仍先识别对象、具体论文/项目和原应用承诺。若工作主张从器件走向逻辑集成/量产，加载 `domains/semiconductor-device-integration.md`；若只研究单管输运或特定射频性能，只加载其相关小节并明确研究尺度。再按原文及独立路线资料核纯度/直径/阵列/接触/介质/工艺/规模/替代证据，不把模块所列潜在瓶颈直接当成已发生失败。

模块示例目前属于规范补充；此轮没有按它完成 CNT 全领域或任一目标论文的完整价值审计，也没有宣称该模块经独立行为验证。
