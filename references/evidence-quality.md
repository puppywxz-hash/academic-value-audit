# 证据质量与来源独立性协议

协议版本：1.2｜适用于主设计 1.4｜日期：2026-10-05。

## 1. 目标与适用边界

防止检索被某一研究共同体、商业利益方或反对阵营的传播内容主导，进而把传播规模、相互引用、奖项或来源名头误当成实证。协议对支持、反对、需求、替代方案以及分析者自己的前提使用相同要求。

本协议是该 skill 的执行规范。其门槛属于本项目的方法设计，不宣称是已有标准规定的统一阈值。正式运行必须读取本协议；简单任务可以缩小问题范围，不能把未评估质量的材料包装成强证据。

不预设某领域存在组织操纵。圈子控制期刊/舆论本身若成为报告结论，也需具体原始证据；共同研究主题、共同公共资助机构、同一学会或互相引用不能单独证明这种控制。可以直接识别证据过度集中、共同来源、选择性报告风险，而不推测动机。

## 2. 复用的原始方法依据

- [Cochrane Handbook 第 4 章，4.6.2](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-04)：将同一研究的多份报告关联，避免多次计算研究；保留其它报告提供的补充内容。
- [Cochrane Handbook 第 7 章](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-07)：分别评估结果的方法偏倚、资助/利益关系和证据综合的风险；按维度记录理由，而不是用一个质量总分替代判断。
- [Cochrane Handbook 第 13 章](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-13)：检索广泛本身仍不足以消除未报告结果造成的风险，应追踪缺失及其可能影响。
- [PRISMA-S 原始方法文章](https://link.springer.com/article/10.1186/s13643-020-01542-z)：为可追溯检索记录提供参考。

上述框架主要服务系统综述，部分针对医疗干预。这里只复用去重、检索透明、分维度评估和缺失证据原则；具体材料、算法、形式证明及定性研究的有效性必须采用相应领域方法。符合 PRISMA 报告格式不能证明结论正确。

## 3. 先规定要证实什么，再选择材料

### 3.1 为每个关键主张写证据需求卡

在选出有利证据之前记录：

1. 主张 ID、准确表述、提出者、时期、范围、是否决定主要结论。
2. 哪些观察或推导能支持它，哪些能反对它，哪些只能说明有人这样说。
3. 目标任务、功能单位、适用工况、合理替代方案和比较时点。
4. 哪些数据、方法或文档必须可见；哪些缺口会限制结论。
5. 需要搜索的证据渠道和依据，不设置支持/反对材料的配额。

纳入/排除依据采用相关性、时间、对象身份、可见范围及方法，不能采用结论立场。发现新机制或关键线索可以修改策略，但必须记录修改原因并对两种方向同样适用。不能为了保留喜欢的结论，临时改变基线或样本范围。

输入策略中的 outcome_blind_selection 表示筛选规则不依赖结果方向；实际是否对审查者遮蔽结果须另行说明，不能据该字段宣称执行了盲法审查。

### 3.2 默认搜索矩阵

专业社区与从业者讨论是“不利与边界结果”及“需求方与实际任务”的实际发现渠道，按[社区调查](practitioner-debate.md)执行。论坛中的原始推导/测量可以直接成为证据；身份断言和经验外推不因此升级。质量契约1.2不变，新增可读争点记录由既有来源、主张和 artifact_paths 关联。

每个关键主张按下列渠道记录 completed、partial、not_attempted 或 not_applicable，列出检索式、平台/数据库、日期、过滤器、访问失败、筛选依据、命中证据及剩余缺口。搜索记录与结果质量分别判断。

直接读取用户文件或原始页面时，记录 direct_retrieval、实际路径/URL、时间及日志位置；不伪造搜索引擎查询。

| 渠道 | 需要寻找什么 | 完成条件 |
| --- | --- | --- |
| 原始工作与更新 | 正文、关键方法/数据、版本、勘误/撤稿、SI 等与主张相关材料 | 回溯到直接依据；未取得则记录可见范围及影响 |
| 机制和先行工作 | 去掉品牌/材料热词后，用功能、机制、结构和更早术语查已有方案 | 能说明候选为何相关及已查时间范围 |
| 需求方与实际任务 | 用户使用、采购/验收、实际运行、维修/失效及真实需求 | 分开规范选择、真实使用和研发目标；营销文案不自动当需求证据 |
| 匹配的替代方案 | 成熟方案、简单方案、其它路线及不采取行动 | 比较单位、时间和工况明确；被忽略候选说明理由 |
| 不利与边界结果 | 复现、null/negative result、限制、退化、失败、成本和效果不显著 | 实际执行适合主题的逆向/中性检索；找不到不等于不存在 |
| 缺失与外部验证 | 注册/计划、项目结果、数据仓库、独立测试和原始使用记录 | 查适用渠道并追踪未披露结果；不适用须解释 |

渠道不是网站名单。一个官方网站可能转发团队宣传，一个行业报告可能受供应商委托，一个竞争者可能夸大缺陷；必须继续回溯数据和关系。同一个索引的不同关键词不自动提供独立证据。

对数学/形式证明等，某些产业渠道可以不适用。对仅核实获奖时间的任务，可直接读取官方记录；不能要求不相关的成本和复现资料。对整体产业价值或公共投入结论，不能因为正面论文已经很多就省略需求、替代和成本渠道。

## 4. 按主张建立来源和证据依赖图

### 4.1 分清单位

- 网页/文件：一个可访问载体。
- 报告/论文：一次表达或分析。
- 研究/数据/证明：产生观察或论证的原始活动。
- 证据单元：能对特定主张提供新增观察、分析或证明的单位。

同一数据由多家机构转述仍是相同观察来源。同一数据的独立再分析可能新增分析证据，不能算独立采集或复现；同一团队的新实验可能产生新增观察，但组织和共同方法偏差仍需记录。证据单元按实际内容划分，不能把整个机构或整个研究领域一律压成一个单元。

### 4.2 每条关键证据的回溯要求

记录原始数据/实验/证明/任务记录 ID、相关来源、版本和位置；边记录为转载、转述、引用同一结果、共享数据、再分析、新测量、共同协议、资助或已核实组织关系。不能仅因背景文献被引用就合并两个独立实验；一篇综述包含多个独立原始研究，也不能把它们整体合并。

检测发现原文无法定位、链条最终只有宣传、或者引用相互承接而没有外部实证时，标为 unresolved/循环承接，不将传播链末端视为新验证。自动匹配只是线索，身份/数据依赖的确认需具体依据；无法确认保持 unknown。

### 4.3 独立性按维度判断

每个关键证据至少评估数据、分析、测试、协议、资助和报告关系，记录相对谁独立及依据。状态为 independent、dependent、partially_shared、unknown 或 not_applicable。

不同单位不必然独立；共同采用公开标准也不必然使实验不独立。利益关联影响风险检查，但不能自动判数据为假。没有披露不能写成没有关联。已知关系必须引用披露、合同/项目、作者或其它原始记录；缺失记录的身份关系不能用模型猜测补齐。

### 4.4 共同前提审计：覆盖整个小同行的框架依赖

多个团队各自采集真实数据，仍可能共同沿用未经检验的应用需求、代理指标、比较对象或价值推导。此时数据可以彼此独立，但这些数据未必能证明共同前提；不能靠来源去重解决，也不能把整个小同行的真实实验合并为一项。

每个决定总体价值的主张，必须展开其前提链，记录下列内容：

1. **问题是否真实存在。** 谁遇到什么问题、现有方案哪里不足？需求来自真实使用/约束、可核实的知识缺口，还是论文背景反复转述的设想？基础研究可以以明确知识缺口为目标，不强制要求工业用户。
2. **指标是否对应目标。** 圈内竞赛的指标是否改变任务结果？材料指标到器件、器件到系统、系统到实际收益的桥接证据在哪里？指标改进和目标收益之间仅有假设时，分别裁定。
3. **基线是否合理。** 是否只比较同路线、过时方案或弱对照，省略简单、成熟、其它路线和不采用新方案？遗漏对照要说明，不为追求否定结论故意选不匹配的基线。
4. **限制是否被排除在评价之外。** 成本、寿命、集成、制造、维护或因果作用等决定性约束，是否被圈内通用实验设计系统性忽略？重复采用一种实验范式不能补足未测量的变量。
5. **共同假设能否独立成立。** 对需求、指标有效性、尺度迁移和经济推导等分别寻找直接依据；它可能来自同领域，也可能来自实际使用、其它技术路线或系统模型。关键是证据回答该前提，不是作者属于哪个圈子。

在台账建立 premise_id，保存表述、类型、相关 claim_id、支持/反对依据、流传来源、验证状态和失效影响。验证状态区分 supported、challenged、invalidated、unresolved、explicit_assumption；引用很多但没有直接依据只能 unresolved。价值偏好单列 normative，不冒充可实验判真的事实。

共享前提风险必须由论文的具体表述、选用指标/对照和证据范围识别，不能仅依据同一学会、共同领域或推测动机。发现前提缺证时，限制依赖它的价值结论，同时保留不依赖它的真实测量和知识贡献。完成圈外检索也不代表完成前提验证；若外部材料仍沿用同一假设，继续记录框架依赖。

## 5. 来源与结果质量分项检查

每条进入关键裁定的证据均保存以下维度的 adequate、concern、fatal、unassessed 或 not_applicable，并给定位、理由及其对本主张的影响。fatal 指不能支持当前主张，不表示该材料的所有内容无效。

评估以证据与具体主张的组合为单位。同一实验可能直接支持性能测量，却不能支持市场需求；分别建立 assessment_id，不给整个来源一个通用可信度。放行记录以拟议判断及时间视角为单位，不能用当前判断的记录替代历史/预测判断。

| 维度 | 检查要点 |
| --- | --- |
| traceability：可追溯性 | 是否看到原始依据，转述是否忠实，原文位置和版本是否可靠 |
| directness：直接性 | 测量/证明的是目标变量，还是代理指标、意见、预测或另一层级 |
| methods：方法有效性 | 对照、测量校准、因果识别、泄漏、假设、形式推导、样本/材料身份 |
| precision_and_variation：误差与变异 | 样本单位、重复、噪声/检测限、分布、区间、最佳样本选择 |
| applicability：适用性 | 任务、工况、尺度、时间、对象、功能单位、真实基线是否匹配 |
| selective_reporting：选择性报告 | 注册/计划和已报告结果是否一致，是否只有有利指标或成功案例 |
| update_status：更新状态 | 版本、勘误、撤稿、后续复现与反证，是否把历史状态当成当前状态 |

独立性和利益关联与这七项并列，不计算统一质量分数。关键维度失效不能靠知名期刊、更多引用、大样本或其它高分补偿。形式证明无需套临床随机化要求，定性研究也不能用数值样本规模替代材料来源和竞争解释。

## 6. 每个关键结论的放行要求

### 6.1 十二项检查

| ID | 放行检查 | 未通过时的动作 |
| --- | --- | --- |
| G1 | 主张范围和需要证明的层次已锁定 | 拆分或缩小主张，禁止宽泛裁定 |
| G2 | 决定性依据可见、来源链和依赖已核查 | 回溯；不足则仅报告谁声称/取得哪些可见材料 |
| G3 | 方法、误差和适用性足够支持拟议表述 | 排除不适用证据、降低表述或保持未决 |
| G4 | 需求/先行/替代/不利等所需渠道实质完成 | 标明检索受限，避免全面或不存在类结论 |
| G5 | 最强的相关反对材料、替代解释及共同前提已处理 | 回到条件/方法/任务；未消解则保留分歧或限定价值推导 |
| G6 | 已核实利益关系、来源集中及小同行共同框架风险已处理 | 针对风险补证据；不按身份定真伪，不冒称独立验证 |
| G7 | 删除依赖转述、重要来源或改变合理假设后的稳定性已检查 | 标明依赖与翻转；无法评估不冒称稳健 |
| G8 | 结论强度与证据一致，剩余缺口公开 | 修改表述，明确可说/不可说及下一项决定性验证 |
| G9 | 已处理披露选择、可观测性与全球/地区来源覆盖；具体线索及反向查漏有记录 | 继续可行决定性取证；区分没有有效证据、机制反证、计量零值和经费行动，不把搜索缺席自动当作事实总价值为零 |
| G10 | 商业事件、长期兑现、资金/成本边界与失败归因支持拟议判断 | 限定到已确认事件；不拼接成熟度，不将整体财务/系统成本代替客户或公共收益 |
| G11 | 证据集合在拟议终点/工况下完成综合，依赖、异质性、缺失和确定性支持措辞 | 拆分条件或终点，补充综合理由，限定或保留未决 |
| G12 | 评价立场、目标前提、适用 M1–M9、行动规模及评价治理已实质处理 | 限定已知贡献，补决策/成本依据，暂缓该强度建议或给条件 |

每项记录 pass、concern、fail、unassessed 或 not_applicable，以及原因、证据 ID 和整改动作。not_applicable 必须有主张相关理由，不能用来绕过核心事实核查。

### 6.2 放行决定与语义

- allow_scoped：没有未解决的实质问题会破坏这一范围内的表述；给准确允许用语。
- qualify：可以交付有条件、来源受限、第一方报告或有分歧的结论；不能包装为已充分证实。
- withhold：当前材料不足以形成该实质判断；输出未决、缺口和下一步。不是停止全部工作，其它已可判断的主张继续交付。

放行是“能否发表该强度的判断”，不是研究是否有价值。一个可靠反例可能足以否定全称主张；一个可检验证明可能足以支持具体形式结论。不设“两家机构”“三篇论文”或“圈外资料占一半”这种真假门槛。

没有独立重复不自动使原始结果虚假，也不自动否定新发现。只有第一方数据时，能否支持有限结果要看具体方法和数据；不能称它已经独立验证、广泛适用或具有确定规模经济性。来源多但独立性 unknown 时，不能宣称形成独立共识。

## 7. 证据集中时必须追加的操作

触发条件针对关键主张：主要实证全部来自同一数据/宣传源；多份材料相互承接但缺少直接依据；关键成本、需求或应用只有利益方的预测；多个团队共同依赖未验证需求/指标/弱基线；或者来源依赖未知足以影响结论。触发不需要先证明组织操纵，也不设一个未经校准的比例阈值。

1. 用机制、功能和任务词重做搜索，跳出团队的品牌/材料名称。
2. 查下游真实任务和已有解决办法，不要求使用某种材料作为前提。
3. 查真正新增数据的验证、失败和限制；圈内研究也可提供有效反证，圈外意见仍须证据。
4. 剥离新闻、宣传和二手解释，只用剩余原始依据重做该结论。
5. 暂时移除决定性来源家族或高风险结果，检查剩余材料支持到哪一层；无材料表示来源依赖，并不证明相反命题。
6. 变换合理基线/参数，判断结论是否仅由某个有争议前提支撑。
7. 仍不能补足时交付 qualify/withhold，并明确独立数据缺口，不能以扩大阅读同源宣传代替补证。

移除利益关联来源属于敏感性分析，不是默认剔除政策。资料减少后精度降低和结论改变需要分别解释；不能把任何敏感性变化都称作造假。

## 8. 报告必须展示什么

对决定总体评价的主张，至少展示：准确命题；最强支持与反对；原始证据单元及相关来源；已知共享关系/利益关联/unknown；分项质量；所需渠道完成情况；放行决定；允许表述；未支持的更强表述；什么证据会改变判断。

存在小同行框架风险时另列共同前提表：多个团队实际测量了什么、共同假设了什么、哪些直接依据验证了假设、假设失效会影响哪一层结论。不能把“数据独立”缩写成“整个价值论证已独立验证”。

来源数、原始研究数、证据单元数按定义实报。独立性未确认不能计成已确认独立。不将上述数量折算为真实性概率。100% 的引用链接完整也只是可追溯性指标，不能当正确率。

### 教学例子：20 份报道实际上支持什么

假设一份团队论文被新闻、奖励介绍、综述及行业报告共 20 次转述；这是假设语料，不是针对实际团队的指控。

- 可以确认：多个材料传播了这项主张。
- 若均来自同一结果：原始观察只有一个来源，转述没有新增观察。
- 原文只有小样本性能测试：最多按其方法支持相应条件下结果；需求、量产成本和现场寿命仍缺证。
- 圈外评论只说“骗人”却无数据：它不构成有效反证。
- 后续匹配工况的独立新实验出现：按其实际数据和方法重新裁定，不能因圈子印象而拒绝正面证据。

### 教学例子：20 个团队都有真实数据，仍不能推出实际需求

假设 20 个团队分别获得某材料的可靠弯曲性能结果，都称该指标将产生重要可穿戴应用价值。其数据不共享，但都没有核实目标用户是否需要反复弯折、柔性材料相对现有产品的实际增益，以及成本与寿命。不能把这些实验当成一份重复数据，也不能把 20 次性能验证当成 20 次需求或经济性验证。

应分别报告：特定工况下性能结果可成立；学术增量逐项比较；实际应用需求与净收益仍需直接依据。若真实任务允许采用更便宜的非柔性方案，需进行功能相同的系统比较；若某个使用场景确实要求柔性且优势得到证实，则单独支持该场景。以上均为教学假设。

## 9. 行为验收规格（未来实施时使用，未在本轮执行）

| 输入情境 | 必须观察到的行为 | 失败条件 |
| --- | --- | --- |

| 第一方有完整严谨结果但未独立复现 | 支持适当范围、明确复现状态 | 自动判虚假，或宣称已独立验证 |

## 10. 数据契约与旧记录

主报告 1.2 新增必需的 quality_audit，主报告 1.3 采用质量契约 1.1，结构见 [证据质量契约](evidence-quality.schema.json)。它关联既有 Source/Evidence/Claim/Judgment，保存证据单元、依赖、共同前提、关系核查、质量维度、渠道、敏感性和放行记录，并新增披露选择、商业兑现与相关放行关联；原有自由文本说明保留。

旧 1.1/1.2 记录不自动当成通过 1.3。迁移需要重新核查这些内容；无法取得的项必须 unknown/unassessed，并重新限定判断。新增数组为空只表示没有记录，适用主张必须关联审计；G9/G10 不适用须有理由。输入由入口补齐质量策略，不要求用户手工填表。

schema 只约束结构；事实真实性、关系成立、原文忠实、搜索充分性及论证有效性仍需语义和领域检查。未来执行程序要检查每条关键证据/主张的记录覆盖、ID 引用、门槛和最终表述的一致性；不能靠非空字符串证明核查完成。

当前报告 1.4/质量契约 1.2 另必需 `method_audit`，见 [决策质量协议](decision-quality.md) 与 [决策质量契约](decision-quality.schema.json)。`claim_reviews` 新增 decision_context_ids、method_check_ids、evidence_synthesis_ids，G1–G12 各一次；每条关键价值判断关联实际覆盖其范围和时间视角的记录。旧 1.3/质量 1.1 需补 M1–M9 和 G11/G12 并重新放行，不能只改版本。

## 11. 披露、传播与可见性审计

本节正式采用用户关于传媒激励与产业保密的要求。复用第 2 节缺失证据原则；原始方法与取得边界见 [方法来源](method-sources.md)。公开资料不是完整随机样本，来源去重后仍要处理没有公开的观察。

### 11.1 逐主张执行

1. 分开当事人表述、新闻稿转述、编辑推断与可复核原创调查，检查可能变已经、组件变系统、试点变成熟市场等表述升级。媒体品牌不定真假。
2. 回溯学术原文后继续检查方法和共同价值前提；不能把论文当无偏真相，把媒体当唯一失真源。
3. 记录已核实披露机制、 plausible_unverified 或 unknown。传媒题材偏好、宣传、保密、专利/发布延迟与访问失败可能影响观察；具体利益/控制关系需原始依据，不能猜测。
4. 用用户任务、型号、功能、工艺、OEM 等词查实际记录；分开产品效果、材料身份、成本和论文归因。已有合法授权的非公开记录可以支持有限判断；未取得的保持未知。
5. 缺失作负面信号前说明应有痕迹、预期依据、可见性、覆盖与替代解释；无依据时只报告缺口，不补检测概率或隐蔽市场规模。
6. 保密不证明成功或失败；公共扩张资金主张仍需相称证据，可以用经授权审查或汇总结果，不要求公开所有工艺，也不宣称统一法定披露义务。

### 11.2 必需记录与放行

`visibility_audits` 逐适用关键主张保存来源、选择机制/依据、预期痕迹与实际可见状态、搜索覆盖、缺失解释及措辞影响；`claim_reviews.visibility_audit_ids` 关联记录。`absence_role` 区分 not_used、coverage_limit 与 negative_signal，后者必须有预期痕迹，语义审查其依据与覆盖。

G9 不能因新闻少判低价值，不能因无新闻补出秘密成功。若局部效果可见、成本不可见，局部效果可放行，经济结论保持限制。纯形式推导等无相关披露问题的主张可 G9 not_applicable，说明理由。

## 12. 商业兑现、失败与公共投入审计

按本节进行主张分层、时间轨迹、队列/删失、失败归因与成本边界审查。原始方法见 [方法来源](method-sources.md)，不得将历史案例当作新对象的正确标签。

### 12.1 逐路线/任务执行

- 保存原始承诺、提出者、范围、目标用户、期限与成功终点。融资/许可/试点/交付/验收/付款/复购/运行分别记录，不设自动递进的价值等级。
- 事件确认程度与验证独立性分开；同一来源重复公告不增加确认。非关联客户也需查采购动机、资金和任务结果，复购不自动证明净收益。
- 分开私人资本、国资股权、科研经费、采购、补贴及未知资金。关联交易不自动虚假；科研设备可以有知识生产价值，须按该任务判断。
- 比较同功能/约束下的替代方案。供应商收入、产品经营、客户净收益与公共回报分别论证。总公司利润不分配到单项技术，未来订单不当收入。
- 成本保存纳入、排除及未知项。尤其检查研发、建设、运行、维护/纠错、退出与外部成本。排除研发的实用性门槛不能直接证明前期公共研发值得。
- 追踪兑现及退出，区分技术、需求、融资和经营失败；并购或失去报道不自动失败。评价行业失败率须另建固定队列和观察终点，报告分母、删失及未知；不得从示范案例计算行业成功概率。
- 应用承诺不成立就下调相应价值。知识增量小且应用价值也不成立，可判低价值；具体知识/反证贡献另行论证，不给每次失败自动赋探索价值。
- 当时决策、现有成果与下一阶段投入分开。细分市场可有高价值；缺少增量收益依据可明确不支持所请求扩张规模，未知不自动给继续投入背书。

### 12.2 必需记录与放行

`commercialization_reviews` 保存关键主张、范围/承诺/终点、事件（日期、发生状态、验证状态、资金类型及依据）、当前终点状态、失败归因与依据、比较/客户收益、成本边界、知识增量证据及下一项验证。`claim_reviews.commercialization_review_ids` 关联记录。G10 不适用须说明，例如只评价形式证明且不作应用/资源主张。

G10 通过只支持其具体命题；允许“某期持续采用”不等于允许“任何场景优于替代方案”。成本或客户数据未见时交付限定判断；反对扩大投入须说明项目目的、请求规模和证据缺口，不能冒称已计算不存在数据的财政回报。

## 13. 新增行为验收规格（实施时使用）

| 情境 | 期望行为 | 失败条件 |
| --- | --- | --- |
| 无新闻而有可靠运行/复购记录 | 评价记录及归因 | 按低热度判低价值 |
| 无资料、有人称因保密而成功 | 保留未知与补证要求 | 推断成功或失败 |
| 记者取得原始测试记录 | 按方法与适用范围评价 | 一律排除新闻载体 |
| 首次交付、许可、融资共同出现 | 分别记录事件与兑现缺口 | 拼接为持续竞争力 |
| 公司亏损但客户收益未知 | 分开经营与技术/客户结果 | 直接证明技术无用 |
| 旧试点无后续报道且企业转让 | 查退出性质与覆盖 | 自动计为技术失败 |
| 大电路优势与小实例用途演示 | 分开任务、尺度和成本 | 拼接成已实现工业收益 |
| 模型排除研发成本 | 保留边界，另审公共回报 | 用模型支持全部投入 |

以上为执行规格，不代表已运行实现或独立行为测试。

## 14. 方法与决策检查的语义要求

- M1/M9 对价值评价适用，其他项依据任务判定；每个情境 M1–M9 各一次，空数组不能代替不适用理由。
- M2 的证据集合覆盖终点、条件和判断，单个可靠证明也能完成综合；不可比实验不能取平均，机制确定性不升级为经济确定性。
- 公共资金、预测、组合和行动结论分别关联适用记录；同一条 partial/unassessed 若限制强建议，放行不能仍写无条件支持。
- `record_ids` 指向该模块的实际记录；context/check/synthesis 引用与主张、judgment、时间一致。M1 指 context，M9 指 governance，M5/M6 可指同一 research_option 但理由不同。
- 确定性标签和放行状态不直接决定正/负价值；对有限、未知或条件化结论可准确放行，对没有证据的强结论不得放行。
- 详规、原始方法来源和适配边界统一在决策质量协议维护。本项目允许明确判定创新增量小、特定应用主张不成立、整体价值低或请求扩张依据不足，前提是范围、覆盖和证据支持该措辞；不以“可能有基础价值”逃避已可裁定的命题。
