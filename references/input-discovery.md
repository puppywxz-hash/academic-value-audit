# 按输入类型发现对象、成果与分析入口

接受少量线索时必读；不是要求用户先提交完整语料。按实际输入加载本文件对应分支，再执行 [获取方法](acquisition-methods.md)、[系统搜集](nonacademic-search.md)和 [两层评价](two-level-assessment.md)。本文件负责“下一步查什么、如何确认关联、何时可以分析”，价值与质量判据仍由原协议负责。

导航：共同流程（1–3）；论文/列表（4）；奖励（5）；个人（6）；团队代表人物（7）；无全文项目/申请书（8）；其它/混合材料（9）；覆盖/续跑及契约（10–11）。用 [发现记录模板](../assets/discovery-record-template.md)保存实际范围、候选、关联、选择与下一项；已有等价记录可复用。

## 1. 路由与首项行动

| 输入 | 先确认 | 接着发现 | 分析入口与首要边界 |
| --- | --- | --- | --- |
| 论文/文献列表 | 标识、作者、版本及实际内容 | 原文/SI、先行/后续、直接相关专利/应用 | 逐篇/工作簇的实际主张；不能由题名/摘要冒称完整方法审查 |
| 奖项/获奖成果/获奖人 | 具体奖项实例、年度/类别/等级、正式成果及完成人/单位 | 规则与成果两条分支；代表论文、专利、转化主体/产品/使用记录 | 先审底层成果，再对规则；不能因获奖直接判高价值 |
| 个人 | 同名身份、机构时期、别名/持久标识 | 公开作品、项目、专利、软件/数据、许可/产品和用途 | 按实际工作簇审贡献，再论其可归属部分；不能只看高被引代表作 |
| 课题组/团队 | 团队边界、主要成员/角色、时期/方向 | 代表人物入口 → 其相关成果 + 团队共同项目/直接成果 | 按用户授权代表范围或全范围审；一人不自动代表所有成员/方向 |
| 申请书/项目号/名称/简介 | 是拟议方案、已资助项目、子课题还是已完成项目 | 原公告/目录/摘要、负责人/单位、公开目标、关联成果/阶段记录 | 无全文仍审可核目标/路线及条件，未读方法/预算保持未知 |
| 专利/报告/会议/混合 | 原对象、阶段/版本、讲者/发明人/机构及对象间关系 | 原报告/权利要求、对应论文、产品和依赖项目 | 分别保留各材料原主张，同一贡献/效益不重复累计 |

奖名可能指整项奖励制度，也可能指某年某个获奖成果。只有笼统“国家科技进步奖”时，列具体候选或请求确定项目/年份；不能自行选一个获奖者当用户对象。输入有可唯一确定的成果别名时自主消歧。人员同名和项目同名同样处理；必要歧义只暂停关联裁定，其它检索继续。

## 2. 共同发现流程与关键词拆分

1. 保留用户原始线索和问题，确认评价对象/时期及已知标识；未确认的候选不合并。检索之前记录需要区分什么。
2. 取得实际可见的官方/机构/对象材料，建立对象简档；宣传文字是其主张来源，不直接验证其效果。
3. 拆关键词与成果形式，分别查论文/专利/代码数据/标准报告/产品及使用记录；新原件反向补别名、编号、人物与转化主体。
4. 对每个命中确认身份/版本、与对象的具体关系及范围，去重成独立贡献工作簇。
5. 合法取得决定性原件、原位置和数据，再接质量规则、系统贡献分析与独立需求分支。未取得的关键部分限制相应结论，不由流畅综述补证。
6. 按决定性缺口排下一项：找范围/身份依据、找原件、解先行/机制争议、验证应用/成本，或记录真实来源限制。不能以第一次无命中或多个相同转载结束。

### 关键词词典

| 词组 | 从原材料拆什么 | 用途 |
| --- | --- | --- |
| 身份/归属 | 中文/英文名、历史机构/组名、法人/品牌、负责人/成员、项目/专利/产品编号、时期 | 找属于该对象的候选，防同名、机构迁移和品牌改名混并 |
| 技术/知识 | 材料与结构、现象/机制、方法/算法、工艺、设备/系统、输出与边界条件 | 恢复实际贡献，查不同术语和相邻领域的先行工作 |
| 功能/任务 | 做什么、给谁用、在哪个工况、改善什么问题/终点、部件/产品/服务 | 跳出成果名查真实需求、替代、失效和系统收益 |
| 成果形式 | 论文/会议/技术报告、专利/软件/数据/标准、样机/产品/许可/采购/部署 | 查不同载体，不能把论文数量当所有成果 |
| 状态与效果 | 试验/发表/授权、许可/交付/验收/付款/复购、运行/停用/退出、实际结果与成本 | 分阶段找记录，不把“转化”一词当已实现收益 |

保留原词、规范化词、同义/旧名、英文/当地语言词及来源位置；审计者推断词标成候选。价值形容词如“重大/突破/领先”登记为待核主张，不能单独当技术检索锚点。论文领域词与专利 IPC/CPC、标准 ICS/CCS、产品型号分别扩展，分类版本及边界留存。

实际查询先用确切标识/题名，再用身份 + 技术/时期，最后用不限定作者的功能/机制及不同成果形式。不是把所有关键词一次 AND 拼接：可能漏掉改名成果、实际转化方和先行技术。每个数据库的语法/过滤/实际读取范围按当时能力记录，不虚构执行过的布尔或日期筛选。

## 3. 关键词命中到确认关联

先区分“检索候选”“来源声称相关”“可核实关联”“贡献/效益归因”。前两者不能直接跳到最后一项。

| 关系 | 有用的直接依据 | 仍不能推出 |
| --- | --- | --- |
| 人—论文/专利/资源 | 原署名/机构时期、ORCID或主页链接及其断言来源、发明人、贡献声明/提交记录 | 每项合著全部由此人创造；同姓/同主题就同人 |
| 团队—成员/工作 | 相关时期成员/职责及单位记录、工作署名和项目角色 | PI全部合著均属该组；成员入组前成果属于当前团队 |
| 奖励—工作簇 | 正式提名/获奖材料中的论著/专利/应用清单、原成果说明 | 完成人的其它论文和后续产品也都属于该奖 |
| 项目—成果 | 成果登记/交付报告、原文资助致谢的项目号、原专利/许可或项目清单 | 一个资助号意味着全部成果由该项目独立产生；可以分配任意收益比例 |
| 专利/论文—产品 | 技术文件、许可/技术转移记录中的精确编号、可核方法/材料/版本对应、使用方记录 | 许可就是实施或产品使用全部权利要求；外形/关键词像就同技术 |
| 产品—使用/效果 | 对应型号/法人/批次/工况的采购、验收、运行和结果/成本记录 | 客户存在即净收益成立；公司总收入都由该技术贡献 |

标识、时期、机制与角色相互核对，矛盾或缺失留在候选/未解决表。没有标识仍可用具体原记录确认，但只有主题相似不能确认。官方目录也可能包含申报方断言或算法链接，需说明来源与核查程度；多个服务复用同一元数据不是独立验证。

## 4. 论文、单条文献与列表

先核题名/DOI/作者/版本，再找出版商、作者/机构仓库、SI/更正/数据代码。只有题名/引文也应尝试取得全文，论文已提供时优先其原件。版本相关不等于贡献等同；会议扩展版有新增内容则单列，重复观察合并。

逐篇恢复主张/方法/结果，按实际问题及机制查原时点最强先行与反例；应用宣传另外查需求和产品/使用。关联专利/产品只纳入与该贡献有关的部分，不自动扩大为作者全部职业审计。用户明确文献列表逐项处理，不能只保留检索易得或指标最好的几篇。

## 5. 奖励输入：规则与成果双向发现

1. **定奖项实例**：官方记录查奖名/年/类别/等级、正式项目、完成人/单位及贡献截止；获得者是多人/多单位就保留实际名单。若输入只是一位获奖人，确认本次要审其哪项获奖成果，或按个人分支保留多个奖与工作簇。
2. **规则分支**：按 [奖励适配](award-assessment.md)取当年规则、细则、指南/评分文件；保留必要条件、允许路径与权重出处。
3. **成果分支**：查提名/推荐材料、成果简介、支撑目录及技术报告；从核心创新、应用对象、材料/方法/系统、完成人/机构和编号拆词。代表作清单是发现起点，不是完整性保证或价值标签。
4. **展开载体**：用正式题名/项目号/完成人及功能机制，分别找原论文、专利/家族、软件/数据/标准、转化主体/许可、产品型号、使用方/采购/运行与效果记录。历史名称与转化主体变更回溯，决定性反对材料同标准纳入。
5. **确定获奖范围**：将当时纳入、背景先行、后续延伸及无关联候选分开。缺公开推荐材料时，可从已知原件恢复范围内关系，但未确认部分不冒充正式报奖清单。
6. **先分析成果，再对规则**：工作簇作两层价值及共享效益/人员归因分析，逐条件返回规则矩阵。原奖时点与当前应用分开；未完整取底层材料时不从现有几篇推整个奖无贡献。

## 6. 个人输入：身份到贡献组合

1. 姓名/别名 + 机构时期 + 研究线索查公开主页/履历和持久标识；将同名候选列开。ORCID缺失不表示无成果，作者ID也不保证聚类正确；发现疑似拆分/混并时回署名和原机构记录。
2. 合并主页、原论文/索引、项目/专利与资源/转化目录的可识别清单，按时期/主题/贡献载体分组；主页自选代表作与独立目录都保留，不按引用阈值过滤。
3. 对每个主题反查原件/关联成果，补历史单位、合作角色和实际贡献依据。找到产品法人/型号后用需求/采购/披露/运行渠道另起取证，不停在作者宣传。
4. 已纳入贡献簇逐批分析；展示知识/科学/工程、应用/社会与资源的实际增量、重复与互补。合著成果有效不自动全归个人；不能归因时保留共同贡献。

默认发现所有可识别元数据、覆盖已纳入的相关工作；未知真实职业全集不称穷尽。用户明确只审代表作/特定时期则按其范围和抽样规则；未获这种选择不静默替个人改成高被引样本。

## 7. 团队输入：代表人物与方向覆盖

先查正式团队/实验室/协作项目、机构与时期，建立主要成员和职责简表。不把整个学校/大研究院当一个课题组，也不把当前网页成员名单套到历史时期。自然语言“某某团队”可能只是领军人物别称，要辨认实际边界。

按用户本技能设计中明确提出的偏好，通常先找代表人物，再沿一人或多人发现贡献；代表人物是取证入口，不是人物价值排行榜。

### 7.1 如何选代表人物

从实际材料提取主要主题、时期和贡献类型，建立“方向/贡献簇—候选人物—角色/原依据—相关成果—可覆盖/尚缺部分”矩阵。按以下依据选择互补人物，不固定人数：

- 负责总体问题/方案且有实际贡献记录的人；
- 对关键理论、实验、算法、工艺或平台有实质贡献的人；
- 对转化、系统交付或独立使用有关键角色的人；
- 历史阶段或不同方向不能由现有人物代表时，查相关时期成员。

PI、头衔、第一/通讯作者、获奖排序和高引用仅是角色发现线索，不单独证明实质贡献。按原贡献声明、项目职责、代码/数据/工艺记录及对应成果判断；角色未知就写未知，不把模型猜测写成团队分工。已有一人覆盖相关单一方向可先从该人进入，多方向/多阶段则补互补人物，不仅挑看起来最成功的例子。

### 7.2 如何接到团队评价

对每位选中人物走个人分支，同时直接查团队共同项目、数据/软件/设备和产品；无个人署名的组织工程贡献不能因此遗漏。合并共同工作簇和共享结果，保留成员各自角色与归因限制，不把多人同一成果累加成多个突破。

区分两种范围：

- **代表人物作为发现入口**：后续覆盖了已约定方向/时期的全部纳入贡献簇，按该限定范围全面分析；入口人物不自动限制发现其它贡献者。
- **只深入代表人物/成果样本**：记录用户明确授权（包括本技能约定）、已核发现框、方向/时期/载体覆盖、选择/排除和未审部分。结论为“所审代表贡献显示……”，不得称团队所有工作或总体比例。若用户要求全团队/职业期全面评价，应继续发现并逐批处理相关工作，不能以代表选择提前结束。

当前设计授权代表分析时使用已有 sampled/purposive 设置，`user_requested=true` 的出处写在 sampling.limits 或运行记录；不得在无授权的其他任务中伪造该标记。不能确认发现框时说明它只是公开可核集合，不声称统计代表性；有代表姓名不等于已经覆盖团队。

## 8. 项目/申请书只有名称、编号或简介

### 8.1 先确认阶段和身份

名称 + 负责人/承担单位 + 资助机构/编号 + 年度查官方公告、目录和原公开简介；分项目、子课题、同名续期/变更以及指南方向。指南要求是资助机构的条件，不等于申请人实际承诺；拟申报题名不等于已立项，立项不等于已经实现目标，结题不自动验证效益。

根据可得依据分别标明拟议/申请、已资助待实施、在研、已完成/结题或阶段未知。不因用户说“项目”就假定存在全文或资金已经支出；项目预算、批准额、拨付、实际支出及研发/运行成本按原边界保存。

### 8.2 恢复公开的项目简档

查项目公告/数据库原条目、公开摘要/目标、任务/子课题、负责人/单位、时期、可得交付/进展/结题报告和成果清单；有合法全文就读，没有就保存可见段落而非重建申请书。用项目号反查原论文资助致谢/成果登记、专利和技术转移记录，再按人/团队及功能词扩展，逐条确认相关关系。

由已读文字拆问题/需求、核心假说或技术路线、拟新增能力、指标/里程碑、预期成果/用途、资源及关键假设。每项标明：原文明确、正式记录补充、关联成果提供背景、审计者条件推断或未知。研究者过去的论文/同名相似项目可说明背景/能力，不可冒充本项目方法、数据或完成成果。

### 8.3 无全文仍能做什么

| 实际取得材料 | 可以分析 | 必须限制 |
| --- | --- | --- |
| 只有题名/编号 | 对象候选、主题/知识问题的背景和待取资料 | 不称已读技术路线、方法有效、预算合理或项目实现了什么 |
| 公开简介/摘要/目标 | 明确目标的需求与先行差距、候选路线约束/替代、可核主张及所需验证 | 不能猜实验设计、样本、隐含方案、全部里程碑/经费；分析是已披露范围 |
| 公开任务/技术路线/指标 | 已披露方案的事前增量、可行性假设、测量/验证和条件性应用潜力 | 未取得细节仍限制有效性/成本；未来无成果不当失败 |
| 进展/结题报告与关联成果原件 | 原目标到实际结果、阶段承诺、具体知识/应用/成本及归因 | 结题手续不自动证明全部主张；无对应目标不能假称原承诺达成率 |

立项/申请的判断是事前理由和方案质量，不要求先有市场兑现。实施/完成项目再独立审实际结果。事后资料可评兑现或解释限制，不能带入原时点假装当时已知。全文缺失不等于不能分析任何问题；也不能把片段分析升级为完整申请书审查。

无原方案时可以审“已披露目标在这些假设下是否值得验证”，但不能归因一个已反证的假设是申请人实际采用。对决定性缺口提出具体所需材料/验证；公开途径不可得时保留受限结论，不要求用户一开始找齐全文，也不擅自发起公开申请/联系负责人。

## 9. 专利、报告、会议与混合线索

专利按公开号/申请号/发明人或主题定位说明书、权利要求、实施例及家族/状态；按原方法/功能找论文及产品。申请/授权、法律权利、真实实现/净效果分开；技术比较不冒称法律有效性裁判。

会议/报告先定讲者、会议/报告名、日期与版本，找日程/摘要/幻灯片/合法录像和对应论文。未看的视频不给时间戳，不能用后来论文替代当时报告所说内容；原宣传主张与论文已测结果分别核。

混合输入各走适用分支，用同一编号/机制/数据/项目证据合并，保留不同材料的时期/主张/范围。产品或新闻是输入入口时按 report/mixed 记录原材料，再逆查明确技术、人员/专利/项目与使用链；不把报道全句当技术原证据。

## 10. 结束发现与转入分析

取证顺序是动态队列，记录“对象/主张—决定性缺口—下一项查询/原件—为何优先—状态—回到哪个判断”。身份/范围矛盾先解决，质量/条件/最强先行及真实需求决定哪些原件值得优先读取；资料容易找不是优先级理由。

范围内每个主要方向/关键主张应已找到适用原件，或有真实取得限制及对应受限结论；候选关系、强先行/替代和决定性不利材料已有处理。不承诺发现所有未知/私有成果；仍有可取得的决定性资料或纳入工作未处理时继续。找到人物/元数据/几篇论文不等于价值分析完成。

报告展示输入到对象到成果再到判断的可追溯路线：身份/关键词、来源/原件范围、关联依据、代表选择、已审簇、未审方向/工作及下一项。所有计数分母注明发现范围，只有申报代表作/样本时不当真实全集；代表分析限制负面和正面总体结论的强度。

## 11. 成熟方法与既有契约

可复用 [OpenAlex 作者说明](https://help.openalex.org/data/authors/) 的作者/作品/机构与名称变体路由，及 [ORCID 来源说明](https://support.orcid.org/hc/en-us/articles/360022948733-Where-can-I-see-the-source-of-information-on-my-record)的断言来源核查；索引聚类/自填记录不保证身份或贡献正确。OpenAlex 的 [awards](https://help.openalex.org/data/awards/) 是资助 grant 条目，不是本技能的荣誉奖项，匹配遗漏也不代表无成果。

项目—成果路线可参考 [NSFC 项目查询官方问答](https://www.nsfc.gov.cn/p1/2961/2962/3648/cx.html)及它给出的结题报告门户、[NIH RePORTER 关联与覆盖说明](https://report.nih.gov/faqs)、[CORDIS 原始项目/交付记录说明](https://www.cordis.europa.eu/about)。检索名、公共/授权访问、分页和身份/关联质量按执行时核查；不假定任何门户能公开全部申请书/个人承担记录。专利按 [WIPO PATENTSCOPE](https://www.wipo.int/en/web/patentscope/)的关键词/编号/分类与原件路线，接回已有家族规则。工具候选和原始指南均不替代真实原件与本技能质量放行。

input 沿用既有 target 类型/identifiers/source_refs/notes；只有名称/简介的项目按 proposal/report 或混合材料性质标注阶段，不新造 project 枚举。报告的人/组/机构建 entity，项目/奖励支撑材料/论文/专利/产品/资源建 work，原件与关联依据建 S/E/C/J。归属用既有 confirmed/probable/unresolved/excluded，取得用实际 access_status/read_scope。

成员、资助、实质复用等关系在确有证据时用已有 member_of/funded_by/reuses 等及 notes；“获奖涉及/可能转化”可保存在原件、work.attribution_notes、关系证据命题和发现表，不捏造 awarded_for/commercialized_as 等 relation 枚举。代表抽样沿用现有 sampling，新增可读发现文件在 artifact_paths 登记；coverage 的 denominator_scope/exclusion_notes 等说明选人/发现/读取/分析差异，不新加 discovery_graph 顶层。
