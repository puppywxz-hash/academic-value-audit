# 功能可比、终端市场与性能指标桥接

适用于输入成果声称产品/服务价值、市场规模、客户效益或性能倍数，尤其是“比传统方法快N倍”“计算优势”“性能提升意味着产业价值”等表述。目标是防止把相邻设备价格、技术标签、峰值指标或一项基准测试挪作终端产品市场证据。

产业/社会资料的机构、记录与查询矩阵按[系统搜集协议](nonacademic-search.md)执行；该参考进一步规定成果功能与终端任务可比门槛。需求侧任务量、真实替代及受益人分析同时遵循[需求与影响方法](demand-and-impact.md)。

## 1. 先判断被审计对象到底是什么

把标题和宽泛名词改写为可检验的功能句：**系统接受什么输入，在什么条件下，输出什么，输出达到什么质量，谁会用它完成什么终端任务。** 原作者命名、媒体称谓和审计者的工程分类分别记录。

例如，论文称“量子计算机”，不能默认其为通用计算机。若论文实际装置仅执行Gaussian Boson Sampling（GBS），对象应先描述为“执行特定光子采样分布的专用实验装置”；若无用户任务数据，不得自行把它扩成优化、药物发现、量子化学或通用计算产品。后续理论架构可行性也不能补成本论文/装置已交付的用途。

在问价格以前，确定本轮的金额问题是哪一种：

| 金额问题 | 需要的对象和证据 | 可支持的判断 |
| --- | --- | --- |
| 成果/系统能以什么价格卖给用户 | 同功能产品的供应报价/公开费率与实际成交/付费服务，连同同类客户/任务及系统配置 | 分别报告卖方报价和已实现交易价；不要把报价当成交或客户需求 |
| 用户为同一终端任务现在花多少钱 | 用户实际购买的最强可行替代服务、内部运行或人工成本 | 替代支出及可能的价值/支付边界；不是本成果售价 |
| 造出/复造/继续研发该系统要花多少钱 | 系统BOM、工程约束、模块交易、人员、集成、验证、运维 | 复造成本或下一阶段增量预算；不是用户需求/产品市场 |
| 该论文过去实际用了多少资源 | 归属明确的项目账目、资产/工时/共享分摊 | 历史成本；不是当前重置价 |

不得把这四问混成一个“市场价格”。如果用户问成果是否有市场，不能用设备复造成本回答；如果问历史财政投入，也不能用厂商报价或另一实验室成交价代替。

## 2. 终端市场价格的功能等价门槛

市场价格资料进入“目标产品/服务价格”或“已验证需求”判断前，逐项比较以下维度：

1. **目标任务与输出**：买方需要完成的是同一终端任务吗？输出是否是同类、可验收的结果，而不只是相同物理过程或相似中间量？
2. **有效质量**：准确度、误差/成功率、覆盖范围、稳定性、吞吐、延迟和验证水平是否满足同一使用要求？
3. **运行边界**：输入准备、编程/配置、校准、前后处理、失败重试、验证、维护和可用率是否计入？
4. **买方与采购目的**：付款者、使用者、预算科目、采购理由和使用场景是否对应？研究设备买家不是终端服务客户。
5. **系统与交易边界**：金额买到的是芯片、设备、集成系统、云时、按次服务还是项目合同？成交、授标、预算、标价和融资分别标注。

作定性放行，不编“相似度百分数”：

- **直接同类市场证据**：目标产品/服务本身或功能等价产品，有可核成交/付费使用，任务、质量和交易边界明确。可用于报告已观察到的市场价格/采用，但不能单凭一笔交易推全市场规模。
- **同终端任务替代支出**：技术不同但完成同一可验收任务、质量与运行边界可比。可作现状支出/用户价值比较；必须标为替代服务价格，不能叫本成果产品售价。
- **工程成本锚点**：部件/实验仪器/研发人员或集成模块价格。只在系统成本模型的相应行使用，必要时辅助估计复造或增量预算；不能作为终端产品价格、客户支付或市场规模证据。
- **相邻/背景材料**：同领域采购、融资、新闻、行业总规模、名称相近的设备或供应商宣传。可帮助发现来源或描述生态，不能进入目标价格/需求估计。

### 报价、交易与市场规模不是同一种证据

即使功能可比，也要准确说清金额处在哪个商业阶段：

- 供应商标价、目录价、云服务费率：证明公开报价/服务费率，不证明有人按该价购买。
- 预算、采购意向、招标最高限价：证明规划或采购上限，不证明已授标、交付或付款。
- 授标/签约金额：证明合同授予/约定金额；除非原件明确付款，不称已付款或实现收入。
- 发票/付款、验收、实际调用：支持一次已兑现交易/使用；仍不能单笔推算普遍支付意愿或市场总量。
- 续约、重复订单、实际服务量及经审计收入：更能支持持续采用；仍须核客户集中度、补贴/关联交易和单位经济性。
- 行业规模预测、融资额、许可/试点公告：最多用于对应的预测/资金/试点事实，不是目标成果的成交价或已验证需求。

市场规模要另有潜在买方数量、真实合格任务量、可达份额、支付/合同与期间边界。一个同类价格证明不了市场量；宏观行业总额也不能按某个成果的技术标签分摊。

若核心维度不匹配，价格证据必须从终端市场估算中排除，并说明它至多可回答什么另一问题。不得因“找到了某个相关采购价”就把它放在市场段落中；可以将它移至成本附件，若成本问题不在范围内则不必收集。

若某层没有足够证据支持价值主张，不要用“没有市场证据”或“未建立可比市场证据”一语带过。分别报告“目标产品/服务报价”“已公开交易/付款”“重复使用/客户留存”“终端任务净收益/可扩张市场”是否找到。公开产品页或历史按量价格属于真实的供给/报价信号，不等于成交；没有找到付款记录也不能抹掉已经核实的服务报价。反过来，一笔付款也不自动证明终端任务有净收益或市场可扩张。

据实际覆盖，使用范围明确的结论，例如：“本轮对下表列明的行业、买方、地区和公开渠道做了定点检索。发现一项历史同类服务报价，但截至审计日未取得可核的实际付费任务、重复客户、同等性能的当前报价或终端行业净收益。因此，公开资料支持‘曾存在有限的GBS云端服务供给/报价’，尚不足以支持‘该论文所示性能已形成持续产业市场或应用价值’。这不是对未检索渠道、私有合同或所有潜在用途的否定。”

这里的“未找到有效证据”必须带对象和判定门槛：是没有找到同任务报价、真实交易、终端用户绩效，还是市场规模证据。没有完成某行业搜索时，写“未检索”；仅读摘要/搜索摘要时，写“线索未核”；发现候选但不等价时，写出不等价在哪一维。不得把“检索无结果”写成普遍不存在，也不得把研究论文/试点/拨款改写成市场兑现。

## 行业/终端任务覆盖表（强制输出）

对涉及应用或市场的成果，正文和检索记录各保留一张行业/终端任务覆盖表。最少拆成：

1. **目标产品/服务本身**：论文实际实现的装置、功能或服务，例如GBS采样设备/云端调用。它回答是否存在同功能产品/服务和相关报价/交易。
2. **原作者声称的每一类终端用途**：逐项按论文中的具体任务拆分，不能把“图优化”“量子化学”合并成一个行业，也不能把一个行业报告当作另一任务的证据。
3. **审计者补充的候选行业/用途**：如有，另标“审计者新增探索”，说明为什么纳入；不得倒写成论文已经声称或证明的应用。

表格至少包含以下字段：

| 必填字段 | 记录要求 |
|---|---|
| 行业/终端任务 | 说明谁在什么工作流中要什么可验收输出；标记作者主张或审计者新增 |
| 目标买方与受益者 | 例如业务部门、实验室、云平台用户、公共机构；付款者与受益者不同则分开 |
| 实际查询 | 原样记录检索式/关键词、同义词、语言、日期；不可将只讨论过的方向写成查过 |
| 地区与渠道 | 列实际覆盖地区及打开过的供应商产品/费率、官方采购/合同、客户案例/年报、监管/项目验收、用户流程等来源；说明未覆盖地区/渠道 |
| 取得与阅读状态 | 区分全文/原件已读、页面局部、搜索摘要、失败/不可访问、仅发现线索 |
| 最强命中及商业阶段 | 分别标注无命中、研究论文、原型/试点、产品页、公开报价、预算、授标/签约、付款/验收、重复订单/运行或经审计收益 |
| 功能可比判断 | 写明任务/输出、质量、全流程、买方目的、系统与合同边界是否匹配；候选证据最多能回答什么 |
| 价值结论 | 在该行业/任务上，明确原价值主张是有直接支持、仅有供给/报价、仅到研发演示、未获支持、或因范围不足无法判断；写出该判断如何影响整体价值结论 |

至少使用三种互不混淆的状态：

- **已检索，未找到匹配候选**：只说明列出的查询/渠道无可核命中。
- **找到候选，但不够资格**：报告候选名称及其差距，例如另一种QPU、只有模拟、研究设备采购、只有资助或无验收试点。
- **找到匹配的报价/交易/使用证据**：注明其真实阶段和可比边界；有报价只能判供给和报价，有付款/验收才判一次交易，有复购/运营和同任务绩效才支持持续采用或净价值。

如该行业只查到算法论文或数值模拟，应直接写“目前证据停在算法/仿真层，未证明真实行业数据上的设备运行、用户任务收益或付款”。如查到研究平台/政府项目，应写明资金购买了什么工作包，是否是研发服务合同；不把它改称终端产品销售。所有行业的价值结论必须落在本行，不能以一个行业的正面案例替另一个行业背书。

### 发现路径与功能筛选必须分成两步

先按目标功能发现候选市场，再逐条通过上面的功能等价门槛。不要先搜一个相邻仪器、凑出一组价格，再用“相关”把它写成目标成果的市场。

1. **用功能描述建检索词。** 组合输入/输出、终端任务、质量要求、服务名称、可能买方/采购部门、采购/云服务/交付等交易词；“量子计算机”等宽泛标签只能作为补充词。按论文主张、专利地域、供需主体位置和任务发生地，选择相关国家/地区、官方采购原件、供应商/云服务价格、合同或付款披露等渠道；使用当地常用语言和别名。
2. **完整执行可得路线并按线索迭代。** 对相关地区/渠道实际查询一般索引及适用的专利、公司、产品、监管、采购/用户入口；分别从成果标识向外、任务/产品类别向内查，补充本地语言、产品名称/型号、法人/专利/客户/功能词，并查该结果通常留下的记录及替代/退出路线。逐条记录查询、命中、原件阅读范围、未取得内容、失败路径及反向查漏。完整全球名册不可得时，不能假称逐项枚举，但不得跳过任何已知可行且可能改变判断的路线。明确区分“未检索”“已检索未命中”“只见摘要”“已读原件但未见记录”“具体记录不可访问”。
3. **再做等价筛选。** 每个候选记录单列任务/输出、质量、系统边界、买方目的、交易状态和金额口径。科研实验设备即使可跨国比价，也仍是设备成本证据；它不会因全球来源更多而变成终端服务市场证据。
4. **说明结果及决策含义。** 逐项报告实际检索的行业/任务、地区/语言、具名入口、命中阶段及没找到的同功能交易/终端收益。完成适用调查仍无有效结果证据时，列出所查行业/任务，并说明该主张不能支持本轮扩大投入；机制反证与计量零值另按来源判断协议论证。不能因为做不到逐笔全球市场普查而减少来源调查，也不声称普查了全世界。该判断不等于售价/ROI为0或整个技术路线永久失败；有事件而金额/净收益未知时保留事件，只把对应数字列为未识别。未证实的正向潜力不给当前价值加分。

**报告结论句先给裁定，再说明调查路径和范围。** 本轮应主动发现并实际查询〔入口、地区/语言〕，追完〔专利/转化/产品/购买/部署/失败〕线索，并依据〔需求/替代/必要机制/通常留痕〕作出判断。完成适用调查仍无有效结果证据时，列出所查行业/任务并说明该主张不能支持本轮扩大投入；机制反证与计量零值另按来源判断协议论证。随后说明这是针对具体对象、层级和时点的价值裁定，不声称全球已不存在任何隐蔽事件，也不延伸到已确认的低阶段结果、其它价值层或未来潜力。若尚有具体且可能改变事件/归因的路线未查，应继续调查，不能称闭环；若只缺金额，事件照样裁定，金额/ROI另列未知。不得把高阶段判断冒充整体价值判断。

地区覆盖矩阵回答“到哪里、通过什么渠道查过”；功能可比矩阵回答“查到的交易能否回答本问题”。两者不可互相代替。

## 3. 速度、效率和规模倍数如何解释

每个性能倍数建立一张“指标桥接”记录，至少回答：

| 桥接问题 | 必须记录的内容 |
| --- | --- |
| 量的定义 | 原始 numerator/denominator、单位、公式、测量对象、测量/估计/仿真状态 |
| 工作负载 | 输入、运行配置、目标任务、任务规模、预处理/后处理及可重复次数 |
| 基线 | 对照算法/系统/硬件、选择日期、是否当前强基线、精确或近似方法、资源/并行假设 |
| 输出可比性 | 输出是否解决同一问题；准确度、误差、成功率、样本质量、覆盖/验证是否相当。若任务是分布采样，写出目标分布、距离/相关性等质量度量、阈值和抽样规模，并核对两端输出是否都达到 |
| 端到端边界 | 输入准备、编程、校准、运行、故障/重试、后处理、验证、维护及服务可用率 |
| 外推范围 | 该结论适用的任务/系统/时点；算法更新、设备改进或物理噪声可能如何改变比较 |

按证据强度分清术语：

- **部件/门内速度**：某一步计算或采样的速率，只描述该步骤。
- **基准任务加速比**：对特定工作负载，在定义清楚且输出质量匹配的基线下，完成同一计算基准所需时间之比。
- **终端任务加速比/生产力**：必须完成同一用户目标并达到同一有效质量，计入数据准备到结果验收的全流程。单一核心步骤更快不自动减少端到端耗时或成本。
- **经济/社会价值**：还需真实任务量、使用频率、全生命周期成本、替代方案、支付/受益及归因。加速比本身不能直接换成钱、产能、市场份额或公共净收益。

若工作负载本身就是被评估的交付物（例如按同一质量标准生成指定分布的样本），可以把结果称为**该窄任务下的样本吞吐/基准加速**；不要把术语扩大成一般用户生产力。要从该指标推出终端任务生产力，还须证明样本/中间产物如何转成用户可验收结果、需要多少样本、质量/成功率是否够用，以及全流程耗时和成本。不得把理论复杂性、希尔伯特空间维数、输入规模、点击数或单步采样率直接换成应用效用。

## 4. 九章1.0例：约10¹⁴窄基准结果与终端任务生产力的边界

以DOI `10.1126/science.abe8770` 为例，论文实际报告的是一个专用GBS装置对特定输出分布进行采样。其约10¹⁴倍数字不是“比经典计算快10¹⁴倍完成任意任务”，也不是生产或社会产出倍率：

1. **分子与分母是采样计算时间**：论文用装置200秒内实际收集的不同click数事件，按各click数对应的经典模拟成本估算；作者说明估算依赖特定高效经典算法、Sunway TaihuLight及每个样本约需计算多个Torontonian。经典机耗时是估值，不是实际跑完了数十亿年的作业。
2. **吞吐数字不验证样本质量**：要比较“生成目标分布的样本速度”，除了计数，还要验证装置输出相对目标分布达到什么统计质量、采用什么检验和阈值，以及经典侧生成的样本是否按同一质量要求计算。论文报告了分布相关验证，但后续针对Jiuzhang 1.0的研究指出原有部分验证检验没有排除一种经典替代解释。因此约10¹⁴这个时间比本身不是“样本与目标分布足够接近”的证明；这条质量/认证链需独立评价。
3. **基准输出不自动等于终端答案**：3,097,810个43-click事件和一个76-click事件说明装置输出的事件数/分布；在GBS基准本身，样本是被计数的计算输出。但论文没有建立这些事件如何转成图问题解、化学预测、可执行程序结果或其他用户可验收产出，也未证明一个76-click事件是更有用的答案。最大click数不能代替典型任务吞吐或合格产出率。
4. **基准本身不含终端问题价值**：即使按论文选定的方法，经典侧生成同规模GBS样本的时间更长，这只回答该特定采样工作负载的吞吐比较；论文没有给出谁需要该分布、它改变什么决策、需要多少样本才够、达到何种应用精度/成功率，或与直接解决终端任务的经典方法相比是否节时省钱。
5. **比较边界不等于完整系统效率**：该数值不表示端到端应用时间或每个合格答案成本；不会自动包含有用输入编码、任务专用后处理、结果验证、维护、低温与控制系统的全成本。
6. **经典基线和实验模型会演进**：论文自身将经典耗时称为估算，并提出后续改进经典算法的竞争。后来GBS算法研究利用实验损耗/噪声优化张量网络模拟；另有针对Jiuzhang 1.0数据的替代经典模型研究。因此任何“当前优势”需按目标版本、具体质量标准、具体算法和数据重新核查。这些后续工作不自动证明原论文没有科学贡献，也不能不经复现就宣称优势全被推翻。

严谨可用表述应是：“发表时作者估算：在其特定GBS采样设定、样本集合和经典算法/硬件假设下，光子装置相对所选经典模拟方案有约10¹⁴量级的样本吞吐优势。该数值是受限采样基准上的条件性比较；论文没有建立它能让某项终端任务多产出多少合格结果、节省多少时间/成本或形成何种市场收益。”再分别评价装置的科学/工程贡献及终端应用证据。**若样本本身就是项目明确的科学交付物，应按采样基准与科学贡献评价，不应因未形成终端商品就抹掉这一窄任务价值；也不可把这一窄价值自动扩大成生产力、产业或社会价值。**

## 5. 输出规则

正文必须解释指标与决策问题之间每一座桥：**原始测量 → 任务能力 → 等质终端输出 → 使用/支付 → 净收益**。每个箭头要有证据；没有证据就停止该方向推断并准确命名缺口。专业版列参数、公式、基线和数据边界；大众版给出同一结论和直观解释。

报告里的价格表分开列“终端可比价格/替代支出”和“成本模型输入”。不要在“市场情况”段落用成本锚点举例。若终端没有可比市场，先报告未识别；是否仍需估工程成本，取决于本次决策问题。

## 6. 方法和事实来源

本方法是对比较边界和证据链的操作协议，不把以下文献当成被审对象市场价值证据：

- Jiuzhang原论文方法细节：`10.1126/science.abe8770`（正文关于200秒样本、Torontonian计时和约10¹⁴估算）。
- 对Jiuzhang 1.0实验验证的替代经典假设：Martínez-Cifuentes et al., *Quantum* 7, 1076 (2023), DOI `10.22331/q-2023-08-08-1076`；该研究指出Jiuzhang 1.0的经典替代解释未被其所分析的检验排除，不等于已证明经典解释正确。
- 对实验GBS损耗影响的经典张量网络算法：Oh et al., *Nature Physics* 20, 1461–1468 (2024), DOI `10.1038/s41567-024-02535-8`；其结果针对实验GBS模拟，主张需逐系统和误差口径读取，不能一概套到所有装置。
